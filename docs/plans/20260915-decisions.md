# Согласованные решения по пробелам boks — 2026-09-15

Предложения разобраны внешним ревьюером (codex, read-only, отдельный контекст): 9 принято как
есть, 8 упрощено, 6 отвергнуто. Ниже — итог после разбора, а не исходные предложения.
Пробелы — `docs/plans/20260915-gaps.md`.

## Главное, что вскрыл разбор: у boks нет памяти о релизах

Четыре отдельных предложения (откат по манифесту, восстановление после обрыва, один env-файл,
манифест в лейблах) разбились об один факт, проверенный по коду: **успешный деплой удаляет
старый контейнер** — `retire` делает `docker stop` + `docker rm` (`internal/deploy/deploy.go`).
Вместе с контейнером исчезают его лейблы, а `keep` удерживает образы, но не состав релиза.
Отсюда: откатываться не по чему, кроме тега; восстановиться после обрыва нельзя, потому что
фактическое состояние не говорит, какой релиз был последним удачным.

**Решение — журнал релизов на сервере**, один механизм вместо четырёх:

- снимок каждого релиза: образ с digest, порты и маршруты, тома, сеть и алиас, режим замены,
  лимит памяти, env-файл; версия формата снимка;
- удерживается столько снимков, сколько `keep` удерживает образов; удаляется вместе с релизом;
- в лейбле контейнера — только идентификатор релиза, без дублирования содержимого;
- журнал операций: до изменений пишется идентификатор операции, предыдущий и целевой релиз;
  после переключения всех маршрутов, снятия устаревших и проверки готовности — отметка о
  завершении, и только потом `retire`;
- повторный запуск под тем же замком доводит незавершённую операцию до конца или возвращает
  предыдущий релиз. Это же закрывает обрыв SSH: локальный список переключённых маршрутов
  перестаёт быть источником правды.

Журнал и замок при этом одни на сервер — после решения автора 2026-09-15 (CLI ходит через control
API) второго пути к Docker просто нет, и договариваться двум путям не о чем. SSH остаётся для
установки, обновления и снятия самого демона.

## Второе: сертификаты чинятся только через живой прокси

`cert.read`/`cert.write` работают через `docker exec boks-proxy` — если прокси не поднимается,
инструмент до файлов не доберётся, а именно тогда они и нужны. Вдобавок два последовательных
`rename` пару атомарно не публикуют: между ними сертификат и ключ несовместимы.

**Решение:** каталог-поколение на каждую выдачу; маршруты получают пути конкретного поколения;
прежнее поколение живёт, пока все маршруты не перешли на новое; возврат — прежние пути. Доступ к
тому сертификатов обеспечивается независимо от состояния контейнера прокси.

## Остальные решения

| # | Итог |
|---|---|
| A1 | `ports` необязательны. Готовность бота проверяется health check контейнера в пределах `deploy_timeout`; без него — понятный отказ. Прокси для приложения без маршрутов не поднимается и не подключается. **Пересмотр 2026-10-06** (`20261006-shchr-gaps.md`, G1): health check — `HEALTHCHECK` образа или блок `healthcheck: {cmd, interval}` в `boks.yml`, который его задаёт или заменяет; было — только `HEALTHCHECK` образа |
| A2 | Слушатель — `tls.VerifyClientCertIfGiven` со своей CA: проверка цепочки штатная, а не своя. Нет сертификата — проверяется сессия passkey. Отдельно задаются доверенные origins и RP ID, защита cookie и CSRF, порядок регистрации первого ключа |
| B1 | Разделитель меняется на точку **только** у сервисов и томов; сеть остаётся `boks-<app>`, как уже записано. Существующие тома переименованием не трогаются — иначе приложение молча получит новый пустой том; нужен явный переход с проверкой владельца |
| B2 | Деплой сверяет фактические сервисы прокси с конфигом и снимает лишние — после готовности новых маршрутов, до `retire`, под общим замком |
| B3 | Строгий разбор конфига: `KnownFields(true)` плюс требование единственного документа |
| B4 | env хранится по релизам в пределах `keep`, режим 0600, запись атомарная; удаляется вместе с релизом. Один перезаписываемый файл отвергнут: он уничтожает значения прошлого релиза раньше, чем новый успел переключиться |
| B5 | Фиксируется `json-file` c `max-size=10m`, `max-file=3` для приложений и прокси; доставка в Loki — через Alloy, как уже предусмотрено. Отдельной настройки драйвера не вводим |
| C5 | Два режима замены: `overlap` по умолчанию, `stop-first` для хранилища с одним писателем. При `stop-first` дожидаться фактической остановки и возвращать старый контейнер при провале запуска |
| D1 | `boks rm <app>`: снимает маршруты, гасит контейнеры, отключает прокси от сети, убирает сеть, env и снимки релизов. Тома остаются без `--purge` |
| D2 | `boks server upgrade` и `uninstall`; область снятия явная — Docker, общий Postgres и чужие контейнеры не трогаются |
| D3 | Перечня артефактов недостаточно. Нужен конкретный протокол: подготовка Postgres с ролями и расширениями, согласованный снимок данных и томов, доступность секретов релиза, порядок запуска — и проверка восстановления на пустом сервере |
| D4 | Список отозванных на сервере хранит идентификаторы (издатель + серийный номер), имя — только для поиска; отзыв проверяется на каждом авторизуемом запросе, включая запросы по установленной сессии |
| E1 | `memory` как жёсткий лимит. Проверка перед деплоем — консервативная, по `MemAvailable` с резервом на инфраструктуру, и с сериализацией допуска новых контейнеров; называется предварительной проверкой, а не гарантией от OOM. Для `stop-first` считается с учётом остановки старого |
| E2 | Приватный реестр по HTTPS: перед `pull` токен из bws (через окружение, где запускается boks: `registry.token_env`) передаётся в `docker login` через stdin, под тем же серверным пользователем и с тем же docker-конфигом; после pull — `docker logout` в любом исходе. HTTP-реестры не поддерживаются. Сделано в #52 |
| E3 | Установка задаёт `default-address-pools` до первого контейнера, проверяя пересечения с существующими сетями и сохраняя прочие настройки демона |
| E4 | Своего механизма уведомлений нет: ненулевой код возврата плюс обработчик отказа планировщика (`OnFailure` у таймера). Уведомление покрывает весь запуск, а не только внутреннюю ошибку продления |
| E6 | Объявленный секрет без значения — отказ до любых изменений на сервере; проверяется результат получения каждого секрета, а не итоговая длина env-файла |
| F | `boks logs` и `--json` у всех команд, с разделением диагностики и данных. `/metrics` **не откладывается** — свои метрики названы (события релиза, результат и длительность деплоя, незавершённая операция, срок сертификата, состояние прокси); их нет ни у cadvisor, ни у node-exporter, а событие релиза вдобавок заменяет `swarm-exporter`, который на простых контейнерах не работает |

управляющий слой не должен.
