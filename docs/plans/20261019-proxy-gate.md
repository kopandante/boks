  одному пути на каждое освобождение и `gated`.

  формата 7 и 8.
- [ ] 5. В log-режиме 24 ч: на каждом хосте расхождение «прокси deny / сайт 2xx» = 0, кроме объяснённых (токены со страниц
  без ip — ожидаемые deny; их число записано).
- [ ] 6. В enforce на хосте 24 ч: доля 401/403 на `/api/*` (кроме auth) не выше доли до включения + mismatch-обновления;
  карточки каталога с ценой (живая проверка на десктопе и мобильном, смена сети Wi-Fi→LTE — один 403 mismatch, затем 200).
- [ ] 7. Токен со страницы (без ip) не проходит; токен с адреса A с адреса B → 403 mismatch; `Set-Cookie: x-api-token` в
  ответах сайта на хостах в enforce несёт значение прокси (с `ip`), а не сайта (R1).
- [ ] 8. Откат проверяется дважды на одной группе:
  - **до чистки сайтов**: `boks server rollback` на ревизию без gate (без env) или `mode: off` + `apply` (с env egress, S5) возвращает
  поведение за < 1 мин; API защищён сайтовым гейтом; сбой обработчика → пропуск;
  - **после чистки сайтов** (не раньше 2 недель enforce без отката): rollback/off = API без токена, поэтому основной путь —
  rollback на предыдущую ревизию с gate; сбой обработчика → 503 по группе, не пропуск (AC13).
  - порядок (T8): «до чистки» проверяется **до** `site_gate: off` — после него откат на ревизию без gate запрещён (S7).
  `site_gate: off` вводится ревизией N, следом ревизия N+1 (любая безвредная правка) — тогда у N+1 есть проверенная
  точка возврата N с `enforce`+`site_gate: off`; после N+1 проверяется: rollback на ревизию без gate — отказ, на N — проходит.

## 1. Context

### Как работает сейчас

**Выдача токена** — роут Next в каждом сайте, модуль `security/api-routes` 2.1.0:
- `registry/security/api-routes/auth/token/route.ts:15-54`: POST, Origin обязан совпасть с Host, если он есть (`:16-24`),
  `Content-Type: application/json` (`:26-29`), тело `{fingerprint}` — 64 hex (`:39-41`, проверка
  `registry/lib/security/fingerprint-server.ts:1-11`). Токен = `createApiToken(fp, getClientIp(request))` (`:43-44`),
  cookie `x-api-token`, `httpOnly:false`, `SameSite=Strict`, `Path=/`, `Max-Age=180`, `Secure` по протоколу (`:6-11,45-52`).
- Отпечаток считает сам браузер (`registry/lib/security/client.ts:17-59`) — значит выдать токен может любой, кто пришлёт
  Origin и 64 hex. Токен доказывает только «звонил в /api/auth/token с этого адреса последние 3 минуты».

**Формат и подпись** — `registry/lib/security/api-token.ts`:
- `base64url(JSON{iat, nonce, fp?, ip?}).base64url(HMAC-SHA256)` (`:35-56`), payload — `registry/lib/security/types.ts:1-6`.
- Секрет `API_SECRET_CURRENT` (≥32 символов, иначе исключение) и необязательный `API_SECRET_PREVIOUS` для ротации (`:8-21,72-87`).
- Срок жизни 3 минуты, проверка по `iat` (`:6,91-98`). Домена, UA, сайта в токене нет.

**Секреты** (bws, проект claude-code, имена `<site>-prod__API_SECRET_CURRENT`; значения не печатались, сравнивались по sha256):
у 13 prod-ключей свой секрет, у **82auto, hanexport, primeauto — один общий** (token-farm.md:51 даёт то же; у hanexport
и primeauto ещё `PREVIOUS == CURRENT`). В контейнер сайта секрет попадает через `.env`, который CI пишет из секрета

**Проверка** — `registry/lib/request-gate/request-gate.ts` 1.7.0, вызывается из `src/proxy.ts` сайта (`createProxy`):
- порядок конвейера (`:13-34`, `:358-405`): адрес → бан (оба слоя, security-сервис) → служебные файлы → `/api/health` GET/HEAD →
  intercept → гео → API-гейт (только `/api/*`, `:399-402`) → заголовки;
- освобождения (`:202-240`): `SECURITY_DEFAULTS.exemptPaths` = `/api/auth/token`, `/api/env-check` (`types.ts:14-18`);
  префиксы `/api/admin/`, `/api/auth/` (`:66`); по сайту `exemptPaths/exemptPrefixes/exemptPatterns`, `gatedPrefixes`
  возвращает префикс под гейт (`:115-135`);
- на `/api/auth/token` — Origin или Referer обязан совпасть с Host, иначе 403 `Access denied` (`:189-200,248-251`);
- токен из cookie `x-api-token` или заголовка `X-Api-Token` (`:253-255`); нет/неверен/истёк → **401 `{"error":"Access denied"}`** (`:256`);
- отпечаток (`:258-280`): заголовок `X-Fingerprint` есть и в токене есть `fp` → сравнение, иначе **403 `Fingerprint mismatch`**;
  токен без `fp` + не-GET → 403 `Fingerprint mismatch`; без заголовка и не-GET → **403 `Forbidden`**; GET без заголовка проходит;
  `skipFingerprintPrefixes` выключает проверку (картинки);
- привязка к адресу: `payload.ip` есть и не равен `clientIp` → **403 `Token address mismatch`** (`:288-289`). Токен без `ip` не проверяется.
- адрес — `getClientIp` = **первый** элемент `X-Forwarded-For` (`registry/lib/security/client-ip.ts:48-57`), доверие

  перезаписывает XFF (`client-ip.ts:29-34`, `lib/security/module.json:39`).
- отказы гейт не логирует (token-farm.md:43).

### Проблема

Исправление гейта = PR в cars-cli + `cars update` + PR, сертификация и деплой в каждом сайте. Последний пример —
request-gate 1.7.0: 6 PR (dbauto#193, 82auto#142, encarexport#155, dkauto#110, primeauto#102, autohubkorea#508,
`scratchpad/impl-gate.md`), и intercar до сих пор на 1.5.0. Плюс расхождения, которые модуль не ловит: свой гейт pakim,
выдача на страницах без привязки у 10 сайтов, общий секрет у трёх.

### Цель

Проверка токена (и выдача) живёт в одном месте — boks-proxy узла hb-sites. Исправление гейта = один PR
(политика в backends или обработчик в boks), без PR в сайтах и без правок клиента `lib/security` 2.5.

### (е) Пути и исключения

- По приложениям (R10): группа ссылается на `app:`, хосты boks берёт из фрагмента приложения — новый хост в boks.yml
  сайта (onestar — 9 хостов) попадает под гейт сам. Группы: 10 шаблонных с HMAC-гейтом (82auto, autogroup, autohubkorea,
  dbauto, glavdoroga, kiramax, koreaautotrade, myencar, onestar, wegugin) + pakim-frontend (свои настройки, R12) +
  **dkauto в `mode: log`** (решение владельца 1). intercar не на узле.
  hanexport, namsuwon, wayexport, heydealer2, encarexport — **вне гейта** (нет HMAC-гейта или клиента); **primeauto — вне**
  (решение владельца 1: каталог закрыт гео). Хосты Convex и вебхуков (`bot.pakim.ru`, `*-convex*`) — вне обязательно (R8).
- glavdoroga: `bearer: {paths: ['^/api/encar(/|$)'], methods: [GET, HEAD], digests_env: GLAVDOROGA_BEARER_DIGESTS}` —
  sha256 Bearer сверяется с дайджестами из `gate.secret`, совпал → пропуск без HMAC; не совпал → обычная проверка (R3).
- Под гейтом: `/api/*` (очищенный путь, как `ban.go:311`).
- Общие освобождения (как `request-gate.ts:66,213` и проба): `/api/auth/` (кроме выдачи токена, которую отвечает прокси),
  `/api/admin/`, `/api/env-check`, `/api/health` только GET/HEAD. Семантика префикса — как `request-gate.ts:202-229`: префикс
  со слэшем освобождает и корень без слэша (`/api/encar/` → и `/api/encar`), `gated` важнее любого освобождения (R7).
- Посайтовые — переносятся из `src/proxy.ts` таблицей: 82auto `^/api/encar/`; kiramax `/api/rates`,`/api/settings` и

### (з) Токен со страницы без ip/fp: чинить ли сразу на сайтах, до прокси-гейта

Прокси-гейт закрывает дыру по построению, тремя независимыми свойствами: (1) прокси не выпускает токенов без `ip`
(POST-выдача — `fp`+`ip`, страницы — `ip`, `fp` сохраняется из проверенного токена сайта, S1/S4); (2) в enforce токен без `ip` получает 401 на любом пути под гейтом; (3) `Set-Cookie: x-api-token` из ответа
сайта получает значение от прокси (с `ip`, R1), так что страница не может выдать непривязанный токен. Каждое свойство проверяется отдельным тестом (AC7).
Вопрос в том, что делать до enforce.

| вариант | что делаем | цена | срок |
|---|---|---|---|
| з1. Ждать прокси-гейт | ничего | дыра открыта, пока все хосты не переведены в enforce. Эксплуатации в журналах не найдено: 401/403 на API koreaautotrade за 24 ч единичные, отказов, связанных с чужим токеном, нет (token-farm.md:40-42) | ≈ 1,5–2 недели: boks PR + образ, 22 бампа, сутки log, enforce по хостам (п. 8) |
| з2. Полная временная мера | `lib/request-gate` 1.8.0: на путях под гейтом токен без `ip` → 401 (одна проверка рядом с `request-gate.ts:288`). В `headers()` 10 сайтов `createApiToken()` → `createApiToken(undefined, getClientIp(request))`. pakim — та же правка своим кодом (`src/proxy.ts:238`) | 1 PR в cars-cli + 10 PR в сайтах (`cars update` + правка `headers()`), 11-й — pakim, intercar прыгает 1.5→1.8. После прокси-гейта всё это снимается (сайтовый гейт → `api: false`), то есть работа одноразовая. ~~Без правки `headers()` 1.8.0 тоже работает~~ — неверно (R1): `<img src="/api/encar/pics…">` (koreaautotrade `car-images.tsx:29`, у 8 сайтов) клиент не повторяет, и картинки первого захода получат 401; 1.8.0 только вместе с правкой `headers()` | ≈ 1 рабочий день: по образцу request-gate 1.7.0 шесть PR прошли сертификацию и выкатку за день (`scratchpad/impl-gate.md`) |
| **з3. Только шаблон** — **выбрано владельцем 19.10** | 1.8.0 и правку `headers()` (`createApiToken` с ip и fp; пункт postInstall) влить в cars-cli сейчас. Сайты получают их со следующим плановым `cars update`, принудительного обхода нет. Если прокси-гейт задержится больше чем на 2 недели или в журнале появится применение чужого токена (403 mismatch с разных адресов, всплеск GET к API без `X-Fingerprint`), обходим сайты по з2 | 1 PR. Дыра закрывается только там, где был update | шаблон — часы, сайты — по ходу |

**Решение: з3** (владелец, 19.10). Полный обход (з2) — это ровно те 11 PR, от которых избавляет прокси-гейт, ради дыры, которую
пока никто не использует. Шаблон при этом перестаёт размножать дыру в новых сайтах. Переход на з2 (укладывается в день) —
по условию владельца: прокси-гейт задержался больше 2 недель или в журнале появилось применение чужого токена.
Уточнение T4 (следствие S2): дыра на сайте закрывается не самим `cars update`, а после его postInstall — `headers()` на

Общий секрет 82auto/hanexport/primeauto (token-farm.md:51) на практике ничего не открывает: hanexport токен не
проверяет (гейта нет, `src/proxy.ts`), у primeauto `api: false`, encarexport тоже `api: false` (`src/proxy.ts:22-23`).

```bash
#   полученным cookie → 200; rollback → time до первого ответа по старому поведению
```

## 7. Критерии готовности (AC)

1. Векторы токенов из TS-кода (≥ 50, включая previous и границу TTL): у каждого вектора два ожидаемых вердикта — сайта
   (1.7.0) и прокси; на валидных и подписи/сроке они совпадают на 100%, расходятся только в помеченных классах
   «прокси строже» (испорченный base64url, R2) и «нет ip» (новое правило) — тест сверяет оба столбца (S11).
2. Все ответы отказа совпадают с таблицей (г) по коду, телу и `Content-Type` — тест.
3. Освобождения каждого хоста совпадают с его текущим `src/proxy.ts` — табличный тест по путям из (е), минимум по
   одному пути на каждое освобождение и `gated`.
4. boks@09b6657 на узле с `gate:` отказывает с понятной ошибкой, ничего не меняя; boks нового пина деплоит сайт на узел
   формата 7 и 8.
5. В log-режиме 24 ч: на каждом хосте расхождение «прокси deny / сайт 2xx» = 0, кроме объяснённых (токены со страниц
   без ip — ожидаемые deny; их число записано).
6. В enforce на хосте 24 ч: доля 401/403 на `/api/*` (кроме auth) не выше доли до включения + mismatch-обновления;
   карточки каталога с ценой (живая проверка на десктопе и мобильном, смена сети Wi-Fi→LTE — один 403 mismatch, затем 200).
7. Токен со страницы (без ip) не проходит; токен с адреса A с адреса B → 403 mismatch; `Set-Cookie: x-api-token` в
   ответах сайта на хостах в enforce несёт значение прокси (с `ip`), а не сайта (R1).
8. Откат проверяется дважды на одной группе:
   - **до чистки сайтов**: `boks server rollback` на ревизию без gate (без env) или `mode: off` + `apply` (с env egress, S5) возвращает
     поведение за < 1 мин; API защищён сайтовым гейтом; сбой обработчика → пропуск;
   - **после чистки сайтов** (не раньше 2 недель enforce без отката): rollback/off = API без токена, поэтому основной путь —
     rollback на предыдущую ревизию с gate; сбой обработчика → 503 по группе, не пропуск (AC13).
   - порядок (T8): «до чистки» проверяется **до** `site_gate: off` — после него откат на ревизию без gate запрещён (S7).
     `site_gate: off` вводится ревизией N, следом ревизия N+1 (любая безвредная правка) — тогда у N+1 есть проверенная
     точка возврата N с `enforce`+`site_gate: off`; после N+1 проверяется: rollback на ревизию без gate — отказ, на N — проходит.

## 8. Выкатка и откат

Выкатка: cars-cli 1.8.0 + `headers()` (з3, сразу) ‖ boks PR → образ → 22 бампа (сайты деплоятся как обычно; узел
остаётся форматом 7, R4) → backends: `proxy upgrade` + `gate` в log (все группы, включая dkauto) → сутки сверки
(`bad_signature` = 0, R6) → enforce на koreaautotrade (небольшой трафик, свой секрет) → сутки → остальные по 3–4 группы →
**не меньше 2 недель enforce без отката** → по группе: предусловия чистки (S3: AC9 при выключенной выдаче `headers()`
на стенде; R8/S8: ни один `/_next/image?url=/api/…` не отдаёт 200 без токена — `curl` по каждому хосту группы) →
AC8 «до чистки» → `site_gate: off` (ревизия N) + ревизия N+1 → AC13 «после» (T8) → чистка сайтов (`api: false` явно) и cars-cli (postInstall, без смены default).

Откат **до чистки сайтов** (сайтовый гейт — второй слой, защита не пропадает): (1) основной — `boks server rollback
hb-sites <rev>` к ревизии 15 или последней без проблемы: без env, секреты с узла (R5), секунды; (2) `mode: off` группы +
`server apply` — **с env пароля egress** (`main.go:476-483` читает его до обращения к узлу; S5); (3) образ — `proxy upgrade` на предыдущий digest (ban8 не знает `boks_gate` → сначала
убрать `gate` из политики, потом образ). Сбой обработчика → пропуск.

Откат **после чистки сайтов** (гейт прокси единственный): rollback к ревизии без gate или `mode: off` = API без токена —
только как осознанная авария; основной путь — rollback к предыдущей ревизии, где очищенная группа в `enforce` +
`site_gate: off` (другие boks откажет, S7; `--force` — только авария). Сбой обработчика → 503 по группе.

Для обоих: `apply` мимо PR-конвейера — только авария, ревизия потом догоняется PR в backends; запускает тот, у кого bws
и WG до узла (Mac владельца), облачная сессия не может — в runbook.

## 9. Non-goals

- Бан, гео, honeypot, rate-limit сайтов и сервис security пула — остаются как есть.
- Сайты без HMAC-гейта (hanexport, namsuwon, wayexport, heydealer2), encarexport и primeauto (решение владельца 1: каталог
  закрыт гео) — не закрываем. dkauto — в гейте, начиная с log (решение владельца 1).
- Устойчивость токена к скрипту (отпечаток собирает клиент, его может подделать кто угодно) — гейт остаётся «доказательством
  визита с адреса», не антиботом. Против распределённого обхода работают ban и эвристики.
- Хранение банов/вердиктов прокси в Redis, другие узлы кроме hb-sites.

## Изменения после ревью (19.10.2026: archify + plan-review + панель codex)

Сверено по свежим клонам `scratchpad/rev-gate/` (boks a337925, backends, cars-cli и 21 сайт, `--depth 1` на 19.10).
Схемы: `scratchpad/plan-proxy-gate-arch.html` (до/после, sequence выдачи и проверки, режимы log→enforce).
Пункты ниже меняют план; места в теле, которые они поправили, помечены ссылкой `(Rn)`.

**R1. Cookie страниц не вырезать, а подменять значение (BLOCKING, нашли схема sequence и codex).**
`<img src="/api/encar/pics…">` у 8 сайтов (koreaautotrade `src/components/catalog/encar/car/car-images.tsx:29`,
`src/proxy.ts:44-45`: под гейтом, только без fp) грузится при разборе HTML, до `initSecurity()` (`client.ts:385-399`);
перехват fetch картинки не повторяет. Сейчас их пускает токен страницы. Если прокси вырежет `Set-Cookie`, картинки
первого захода получат 401. Решение: на хостах группы в enforce обёртка ответа **заменяет значение** cookie
`x-api-token`, поставленного сайтом, токеном прокси `{iat, nonce, ip: client_ip}` (без fp; атрибуты cookie сохраняются).
Когда ставить, по-прежнему решает сайт («только если нет или невалиден»). Дыра закрыта: ни один токен без `ip` не
выходит наружу. Послабление 1.7.0 (токен без fp на GET с `X-Fingerprint`) остаётся — оно нужно этим токенам.
В log обёртка ничего не трогает. Обёртка обязана пропускать Flush/Unwrap (потоковые RSC); тест на TTFB страницы.
Тот же довод опровергает строку з2 «без правки `headers()` 1.8.0 тоже работает» (поправлено в теле).

**R2. Контракт выдачи: 6 вариантов route.ts, отличия не влияют на клиента.** Хэши: шаблон cars-cli = dkauto, glavdoroga,
onestar; autohubkorea, dbauto, intercar/myencar/wegugin отличаются комментарием и порядком импортов; 82auto,
koreaautotrade, primeauto, pakim-frontend строят ответ отказа на каждый вызов (у шаблона общий `REJECT` на модуль —
повторный отказ может уйти 500 «body already used», 82auto `route.ts:13-16`); autogroup и kiramax ставят `Secure` по
`NODE_ENV` (в проде всегда), остальные по протоколу. Прокси отвечает: 200 `{"ok":true}` + `x-api-token=…; Path=/;
Expires=…; Max-Age=180; Secure; SameSite=Strict` (Next добавляет Expires); 403 `{"error":"Forbidden"}` на CT/тело/
отпечаток, 403 `{"error":"Access denied"}` на чужой Origin/Referer (`request-gate.ts:189-200,249`). Тело — не больше 4 КБ
(у pakim-frontend потолок 413 на весь `/api/*`, `src/proxy.ts:151-166`). Клиенты: 2.5 обновляет на 401 и 403 с `mismatch`
(`client.ts:117-125`); intercar 2.4 и pakim — на любой 401/403 (`client.ts:283`, pakim `:127`). Все совместимы.
Совместимость формата для сайтовой проверки токенов прокси (двойная проверка): `iat` в мс, число;
`Buffer.from(…, "base64url")` у сайта всеядный (паддинг, `+/`), Go `RawURLEncoding` строгий — прокси может быть строже
сайта только на испорченных руками токенах; векторы AC1 включают такие случаи с ожидаемым «прокси строже».

**R3. glavdoroga: Bearer-партнёры (major, нашли ревью и codex).** Форк request-gate с хуком `trusted`
(`src/lib/request-gate.ts:140,259`): GET/HEAD `/api/encar/*` с Bearer из `ENCAR_BEARER_CLIENTS` (sha256 + timingSafeEqual,
`src/lib/security/encar-bearer.ts:74-94`) проходит без HMAC — партнёр тянет каталог сотнями запросов в минуту
(`bearer-traffic.ts:5-7`). Без переноса enforce отрежет партнёра. Решение: в группе `bearer: {paths: ['^/api/encar(/|$)'],
methods: [GET, HEAD], digests_env: GLAVDOROGA_BEARER_DIGESTS}` — прокси сверяет sha256 токена с дайджестами из
`gate.secret` и пропускает; несовпавший Bearer идёт обычной HMAC-проверкой. Освобождать по одному наличию
`Authorization` нельзя. Счёт трафика и лимит партнёра остаются в сайте. Тест: валидный/чужой/пустой Bearer, POST с Bearer.
Отдельно в log найти, кто шлёт `X-Api-Token` на cars.dbauto.kr (1 005 за 24 ч, token-farm.md:36) — до enforce dbauto.

**R4. Формат 8 запирает флот при первом же деплое (BLOCKING, нашёл codex, подтверждено).** См. поправку в (ж).
Решение: boks нового пина читает форматы ≤ 8, а **пишет** 7, пока в политике нет `gate`, и 8 — только когда есть
(`FragmentFormat` из константы превращается в функцию политики; маркер `_server.json` — так же). Тест: новый boks
деплоит сайт на узел без gate → фрагмент «7»; boks@09b6657 после этого деплоит без отказа; после `apply` с gate — отказ.
Плюс, чтобы «одно исправление = один PR» оставалось правдой и дальше: `gate` в политике хранится как непрозрачный JSON,
boks кладёт его в конфиг обработчика как есть, а проверяет схему Caddy при reload (`DisallowUnknownFields`, старый конфиг
остаётся). Тогда новое поле гейта = новый образ + ревизия политики, без нового формата и без 22 бампов.

**R5. Рубильник: до и после чистки — разные процедуры (major, codex + ревью).**
- Основной рубильник — `boks server rollback deploy/egress/boks/hb-sites.yml <rev>` (S5): не требует env (секреты берутся с узла), секунды. Для этого
  `gate.secret` при `apply`/`rollback` без env берётся с узла, как `loadSecret` у egress (`policy.go:194-213,330-333`), —
  иначе `mode: off` потребует все секреты групп и пароль egress из bws.
- `apply` идёт мимо PR-конвейера только как авария; ревизия потом догоняется PR в backends.
- Запускает только тот, у кого есть bws и WG до узла (Mac владельца); облачная сессия не может — записать в runbook.
- **После чистки сайтов** off/rollback = API без токена вообще (выдачи на сайте нет, проверки нет), а `recover → пропуск`
  = обход единственного гейта. Поэтому: (1) паника в enforce после чистки → 503 по группе, не пропуск; до чистки — пропуск;
  (2) чистку сайтов (route.ts, `api: false`) делать не раньше, чем гейт прокси отработал 2 недели без отката; (3) AC8
  проверяется дважды — до и после чистки.
- Отказ самого прокси — не новый риск: он и так вход для всех хостов. Новый риск — логический: один образ/политика роняет
  API всех хостов в enforce; поэтому enforce по одному хосту и rollback — основной путь.

**R6. Проверка секрета.** `/api/env-check` освобождён от HMAC (`types.ts:14-18`) — ложный успех. Замена: в log прокси
считает `bad_signature` по группе; 0 на ≥ 24 ч при живом трафике = секрет прокси равен секрету сайта. Это условие входа
в enforce (AC5).

**R7. Семантика освобождений.** Префикс со слэшем покрывает корень без слэша (`request-gate.ts:205-209,225-229`),
`gated` важнее всех освобождений, `exemptPaths` — точное совпадение с методами. В политике три типа: `exact`, `prefix`,
`regex`; 82auto — `prefix: /api/encar/`, а не `^/api/encar/`. AC3 расширяется: корень, потомок, похожий чужой префикс
(`/api/encarx`), пересечение gated/exempt.
Путь для решения — очищенный (`path.Clean`, как `ban.go:311`), и его же видит Next (WHATWG URL схлопывает `..` и `%2e`).
На хостах группы `/api/*` с `%2f`, `%5c` или `\` в сыром пути — 400: Go и WHATWG разбирают их по-разному
(`/api/admin/..\encar` Go считает под `/api/admin/`, WHATWG — `/api/encar`). Тест: сырые пути через `curl --path-as-is`
против Caddy+Next на стенде, вердикт прокси против обработчика, до которого дошёл запрос.

**R8. Серверные вызовы, Server Actions, RSC.** Серверных вызовов сайтов к своему публичному `/api` в коде нет (поиск
`fetch(\`${…}/api/…\`)` по 12 сайтам: Convex, переводы, уведомления). Хосты Convex — вне групп обязательно
(`/api/query|mutation` у Convex). Server Actions и RSC — пути страниц, гейт не трогает; обёртка cookie их касается (R1).
Проверить **до** чистки (предусловие, S8, п. 8): `/_next/image?url=/api/encar/pics…` — оптимизатор Next ходит за картинкой внутри контейнера,
мимо прокси; если хоть один сайт отдаёт pics через `next/image` без `unoptimized`, после чистки это обход гейта.

**R9. Переход и адрес клиента.** Двойная проверка в enforce держится на `getClientIp` сайта = `client_ip` Caddy. Сейчас
так на всех хостах групп (прямые; на koreaautotrade remote≠client за 24 ч — 0, token-farm.md:33). Если хост уедет за CF
или hb-edge, а сайтовый гейт ещё стоит, посетитель со своим XFF (корпоративный прокси) попадёт в петлю: прокси выдаёт
токен на `client_ip`, сайт сравнивает с первым XFF → 403 mismatch → новый токен с тем же адресом. ~~Правило: `server apply`
отказывает, если хост группы в enforce есть в списке хостов за CF, пока у группы `site_gate: on`.~~ (S13: списка хостов
за CF в политике нет — только комментарий `hb-sites.yml:6-16`, и перевод DNS apply не запускает.) Правило: на хостах
групп гейт перед проксированием переписывает `X-Forwarded-For` в один адрес — `client_ip` (в любом режиме, кроме off);
`getClientIp` сайта тогда совпадает с адресом токена при любом маршруте. Тест на цепочки XFF
direct / hb-edge / CF, включая XFF посетителя слева. Сравнение строк адреса: Caddy даёт `netip` без зоны и с Unmap (`ban.go:281-293`), сайт — строку XFF
от Caddy; векторы с IPv6 и IPv4-mapped.

**R10. Группы — по приложению, не по списку хостов.** onestar держит 9 хостов, и новый хост, добавленный в boks.yml сайта,
по списку в server.yml молча останется без гейта (а после чистки — без защиты). В политике группа ссылается на `app:`,
хосты boks берёт из фрагмента приложения при сборке конфига.

**R11. Вердикт не в ответ, а в журнал.** `X-Boks-Gate-Verdict` в ответе подсказывает обходчику, что думает гейт. Вердикт
пишется в доп. поля журнала доступа Caddy (`caddyhttp.ExtraLogFields`), в ответ — ничего, кроме тех же тел, что у сайта.

**R12. Список «вне гейта».** dkauto и primeauto **не** «без клиента»: клиент и выдача у них работают, `api: false`
выключает только проверку (у primeauto причина записана: «каталог закрыт гео целиком», `src/proxy.ts:83`; у dkauto
причины в коде нет). Исключение из групп верно для поведения «как сейчас», но (1) включение им — строка в политике, без
PR в сайте (вопрос владельцу Q1); (2) при чистке cars-cli 2.0 нельзя удалять у них route.ts, не убрав `initSecurity()`
— иначе 404 на `/api/auth/token` каждые 2 мин с каждой вкладки; (3) правило ban `token` (backends, п. 4) считает и их выдачу.
intercar не на hb-sites — убран из плана. pakim — только pakim-frontend (`cars.pakim.ru`); у него свои отличия: 401
`Unauthorized`, `/api/admin/*` полностью вне HMAC, нет послабления 1.7.0 (GET с `X-Fingerprint` и токеном без fp → 403),
токен страницы на **каждом** ответе с `fp/ip` из старого токена (`src/proxy.ts:226-250`) — группа pakim получает свои
настройки, и R1 подменяет его cookie так же.

## Изменения после ревью, раунд 3 (19.10.2026: plan-review свежим агентом + панель codex)

Сверено: свежие клоны `scratchpad/rev-gate3/` (boks a337925 = origin/main, backends, cars-cli, koreaautotrade,

**T1. S3: критерий своей cookie — по запросу, не по ответу (major, ревью + codex).** «HTML на GET» по `Content-Type`

`src/proxy.ts:20-23`) и первом XFF из диапазонов CF — после перезаписи это не выполняется. Строковое совпадение адреса
(IPv4-mapped, IPv6) проверяется через полный конвейер Caddy→сайт, не только unit-тестом (codex).
